# BankRAG v2 技术设计

## 请求流程

会话归属校验 → 统一意图/范围判定 → 有效 FAQ 匹配或 RAG 检索 → 引用编号、标题及文档块 ID 校验 → 统一免责声明 → 保存脱敏会话。

所有同步模型、SQL、Redis 和 LLM 调用通过线程工作区执行；API 设置有限并发，同一会话串行，避免上下文顺序混乱。MySQL 每次操作使用独立连接和事务。

## 知识与检索

文档 SHA-256 绑定审核注册表；逻辑文档 ID 与内容版本分离；父子块 ID 稳定且含文档身份。正文显式日期优先，整理日期不等于生效日期。旧声明过时的问答进入 rejected。

Milvus 只召回 demo_approved、CN 且日期有效的记录。source_filter 使用枚举白名单。稠密与稀疏 ANN 共同过滤，单候选仍重排。构建完整新快照、核对数量、加载后切换别名；失败不切换，保留一个旧快照回滚。导入必须单写者执行。

FAQ 使用规范化问题指纹唯一键；完整导入在事务中替换并发布知识版本。Redis 使用 BankRAG 命名空间、知识版本和固定 TTL；读取命中仍回查数据库，导入主动失效，不清空 Redis 全库。

## 输出与溯源

结果统一包含 decision、intent、citations 和内部 contexts。引用 ID/标题由服务端绑定；缺失、越界或虚构标题时返回信息不足。未完成独立的逐句语义支持证明。

流式模式先交付免责声明，缓存模型内容完成校验后分片交付，防止未经检查的部分答案泄露。网络断开后的最终帧无法保证送达。

## 测试与局限

回归替身测试和真实本地联调分开记录；历史成绩不沿用。固定集合带版本和哈希，RAGAS 使用实际生成 trace，逐题保存并披露回答覆盖率。

详见 remediation_report.md。当前属于学生演示 MVP；银行认证、独立合规审查、完备 PII 识别、分布式导入互斥、压测、灾备和全新部署认证尚未完成。
