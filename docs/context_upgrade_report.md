# BankRAG 本轮改进与真实验证报告

## 1. 结论与范围

按已认可的顺序，已完成意图规则改造、CPU重训及模型替换、有限事实支持与条件校验、多轮产品指代、请求级检索诊断、自动化回归及待评材料工具。**独立人工评分仍为0**，用户明确选择先交付待评材料，因此未虚构人工一致性、裁判可信度或新的RAGAS成绩。

EduRAG代码未改；本轮凭据及其加载逻辑未改。原模型与变更前代码保存在 `.context_upgrade_backups/context_v2`、`context_v2_1`、`context_v2_1_1`。

## 3. 训练的真实结果

- 最终语义族版本 `context_v2_1`：训练42族/368条，验证13族/112条，语义族交叉0；全部标签在两侧均有样本。
- CPU实际耗时 281.4 秒；5轮全参数微调，从本地 `bert-base-chinese` 初始化，未安装CUDA。
- 开发验证匹配109/112（97.32%）。同族变体仍是相关样本，不能视为480个独立场景；分组由开发者人工定义，不证明不存在更高层语义重叠。
- 旧回归110轮暂定标签：纯BERT从57到106；在同一当前规则/指代模块下，旧模型80、新模型109。历史原规则为60。三种口径不能混写。
- 这些标签未经独立人工审定，且旧测试已参与开发分析，故不发布其为独立泛化准确率。
- 原始候选 `context_v2` 只有基础请求分组，划分不够严格；它的100%开发分数不用于结论。30轮已执行接口结果中止保留，没有删除挑分。
- Windows换行造成初始训练清单的文本哈希与实际字节哈希不同，现已修正清单声明；数据行和模型权重未因此变化，并补字节哈希断言。

最终权重SHA-256：`bd1a46cb3f403ea8db63814c618ee2640e66743ee99d99ff3f975e824ef7b48a`。

## 5. 已发现的剩余问题

1. **P1 检索缺口**：H-B01的目标证据父块已召回，实际重排分数0.037538低于0.15而被淘汰，HTTP/WS一致；已用冻结gold原文对照parent_content和块ID核实。下一步对查询改写、父块长度、重排校准分别做开发集实验；不直接降低全局阈值。诊断见 `evaluation/results/context_v2_1_1_development/retrieval_source_diagnosis.json`。
2. **P1 事实检查仍不完整**：有限数值检查可能拦截正确题设或算术结果；不覆盖所有非数值断言、条件、否定和跨句蕴含。下一步需要经过人工确认的事实/条件开发样本及明确支持映射，不能把规则通过视为金融事实正确。
3. **P1 标题别名/资料不足**：C06加入被引用材料的真实一级标题别名后，HTTP/WS专项均恢复回答；M01第二轮产品指代亦均恢复回答。P07在最终补丁中仍遗漏最低支取条件，已被拦截为信息不足，因此安全拦截成功不计业务回答成功。详情保存在 `evaluation/results/context_v2_1_1_development/context_targeted_findings.json`。其它被拒标题仍须根据脱敏记录核实官方别名，不能开放任意标题。模型无引用地表示不足时，服务端仍会记录引用校验失败并返回安全不足答案。
4. **P1 泛化证据不足**：当前只有合成开发数据和已知回归样本；真实用户表达、语义族定义及标签需要人工复核，不能据97.32%或109/110宣称生产级意图准确率。
5. **P1 人工与裁判**：最终43条可用FAQ的支持文件均通过哈希/期限检查，其中42条通过有限事实规则，零存整取漏存FAQ的“一个月”题设复述被数值规则保守拦截，回落RAG；这不是已证实的业务事实错误。先完成双人独立事实评分，再裁决分歧并计算裁判误接收率；模型裁判不参与自动补齐人工分数。待评状态保持pending，不生成0%或100%的虚假成绩。
6. **P2 响应时延**：策略选择/多查询与完整缓冲都会增加首正文时延；以后应依据候选质量做成本和延迟评测，不能以早发免责token冒充正文即时流式。
7. **P2 运维**：仍是学生作品/MVP；未认证全新环境、Docker部署、生产身份认证、并发压测、灾备或监管合规。

## 6. 待评材料和下一步

- `evaluation/review_context_v2_1`：完整回归的匿名双评材料；`review_queue.jsonl`可分别复制给评审，`private_mapping.json`不分发。
- `evaluation/review_context_v2_1_1_targeted`：最终补丁的专项材料，22轮，不能与220轮当作同版同批混算。
- `evaluation/review_judge_calibration_v1_1`：针对历史首轮裁判的同批校准材料，预登记样本见manifest；与新回答的评分严格分开。
- `evaluation/reserve_v2_candidates`：新30场景/33轮候选，未运行/未外发，先独立审题和来源核验；确认gold和污染筛查后再另立正式执行版本。

用户目前没有独立评审，故这些工作待评。工具要求先完成全部预登记样本的真人评核；有效裁判匹配至少30条，且人工通过/失败各至少5条；裁判格式错误另计，不隐藏筛掉；否则指标为null并标明不足。即使0次误接收，Wilson区间也不会虚标成无不确定性。该区间只作独立行假设下的参考；同场景跨HTTP/WS及多轮存在相关性，正式统计应再按场景聚合或做聚类区间，不能当独立总体置信区间。

建议后续顺序：真人核验标签与事实 → 基于诊断修复检索和条件支持 → 固定新版本 → 运行经独立审题的新保留集。当前无需因旧回归高分立即再次重训。
