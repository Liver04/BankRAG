## 4. 数值与多条件的实现边界

1. 用户给出的利率/费用不能成为银行事实。回答手续费时，不能借同一引用里的起存金额证明费用。
2. 明确的漏存月份、已持有时长可作为题设复述；“合同规定允许漏存”等银行规则断言仍须原文支持。
3. 通知存款只对明确的人民币金额条件、唯一且一致的原文门槛做精确比较。总额减支取额可以推导剩余额；不推导未来收益。题设矛盾、来源冲突、缺项或外币情形不套用人民币计算。
4. 每项金额条件分别引用真实块。即使两项满足，也明确其它预约、账户和办理条件仍须核对，不承诺操作成功。
5. 一般生成路径仅在“遗漏受支持条件”时允许一次内部重答；不修复并放行编造数字、越界引用、虚构标题或危险输出。所有文本在校验后才交付WS。

服务内的一次条件修复是明确记录的业务流程，不是评测重试或多次运行挑高分。最终trace含generation_mode、条件计划、数值来源、repair初始原因和最终状态。
