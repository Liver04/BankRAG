# BankRAG 新增保留测试包 v1.0.0

**100 场景 / 110 轮，尚未运行。** 这是开发后的保留测试集候选版；作者已看过实现，不是第三方双盲。所有题目的机器起草答案依据均待独立人工审定，不能把预检通过写成问答准确率。

## 一、覆盖分布

| 类别 | 场景数 | 重点 |

| P 产品细则 | 14 | 计息日期、提前支取、转存、漏存、留存条件 |
| B 公开业务 | 12 | 代理开户、分类账户、转账、存款证明 |

按行为计数：52可回答、14拒答、20转人工、16说明不足、3澄清、5闲聊。两个 transport 的同题不是两道独立知识样本。

## 二、如何使用

1. 审题人读取 [人工核验标准](../../docs/holdout_review_standard.md) 和 [题目核验手册](casebook.md)。逐题确认题意、依据、范围和语义独立性，填写 review_records。
2. 本包与旧开发集分开，禁止入知识库、训练集或调参集。正式首轮前固定题目、gold、知识及代码版本。
3. 执行器只读 questions.jsonl，不能向模型发送 answer_key。保留实际上下文和全部失败；同一多轮场景沿用实际会话。
4. 本轮没有新增在线执行器；旧 compliance_evaluate.py 的固定数据路径和逐题新建会话不适用本包。不要覆盖 cases_v2.json。
5. 独立评审人工评分，必要时复核/裁决。结果未经评分不能写为通过。
6. 首轮后用于修复时，本包就成为回归集；再建另一个未曝光的保留集衡量泛化。

## 三、离线完整性检查

在项目 qa_system 目录、已激活的Python环境中执行：

```cmd
python -B evaluation/holdout_v1/validate_pack.py --output evaluation/results/holdout_v1_preflight.json
```

此命令仅检查文件、结构、引用原文、哈希、已知旧题重复和运行代码未变；**不调用模型、云API或数据库，不产生准确率。** 若代码、模型或知识已升级，freeze相关检查失败是漂移提示，不能通过删除失败项宣称版本一致。

## 四、文件说明

- questions.jsonl：100行，一行一场景；多轮用turns顺序表示。
- answer_key.jsonl：100行，110轮期望行为、逐点标准、禁止结果、原文位置与doc/version。
- casebook.md：可直接浏览的题目与核验锚点。
- review_records.jsonl：110行空白核验表；两位评审、事实到引用映射和裁决栏位。
- contamination_audit.json：31个已知文件、2,511个去重旧文本的精确/字面筛查；含保守收集的测试中文常量，不全是实际题目。
- source_snapshot.json：24份Markdown资料的内容与审核/日期/地区快照。
- runtime_freeze.json：当前运行代码、BERT权重等的SHA-256，配置仅含哈希。
- design_summary.json：场景和行为分布，明确not_run/pending。
- review_examples.md：评分口径的假想例子，不是系统实测输出。
- source_checks.json：仅对发现的资料冲突作局部官方来源核查；不宣称全库法律复核。
- manifest.json：正式文件哈希和冻结说明；验证结果另存在evaluation/results，避免把结果循环纳入自身哈希。
- validate_pack.py：独立标准库校验器。

现有真实联调和7条RAGAS仍属于旧开发集；本包未产生新分数，不覆盖旧结果。完整准备报告见 [holdout_preparation_report.md](../../docs/holdout_preparation_report.md)。
